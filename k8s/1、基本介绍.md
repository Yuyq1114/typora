# Kubernetes（K8s）详细介绍

## 一、什么是 Kubernetes

Kubernetes（简称 K8s，8 代表 K 和 s 之间的 8 个字母）是一个开源的**容器编排平台**，最初由 Google 基于内部系统 Borg 的经验开发，2014 年开源，后捐赠给 CNCF（云原生计算基金会）。它用来自动化容器化应用的**部署、扩缩容、运维和管理**。

**它解决的问题：** 当容器数量从几个增长到几百上千个，分布在多台机器上时，就需要解决：

- 容器该调度到哪台机器上？
- 容器挂了谁来重启？
- 流量高峰如何自动扩容？
- 如何不停机地升级版本？
- 服务之间如何互相发现和通信？

K8s 就是为这些问题提供统一答案的系统。

## 二、核心架构

K8s 集群由**控制平面（Control Plane）**和**工作节点（Worker Node）**组成。

### 控制平面组件

| 组件                         | 作用                                                         |
| ---------------------------- | ------------------------------------------------------------ |
| **kube-apiserver**           | 集群的统一入口，所有操作都通过它的 REST API 进行             |
| **etcd**                     | 分布式键值数据库，保存整个集群的状态和配置                   |
| **kube-scheduler**           | 负责决定 Pod 调度到哪个节点（考虑资源、亲和性、污点等）      |
| **kube-controller-manager**  | 运行各种控制器（Deployment、Node、ReplicaSet 等），不断让"实际状态"趋近"期望状态" |
| **cloud-controller-manager** | 与云厂商 API 对接（负载均衡、云盘、节点等）                  |

### 工作节点组件

| 组件           | 作用                                                         |
| -------------- | ------------------------------------------------------------ |
| **kubelet**    | 节点上的代理，负责管理 Pod 和容器的生命周期，并向 apiserver 汇报状态 |
| **kube-proxy** | 维护节点上的网络规则，实现 Service 的负载均衡                |
| **容器运行时** | 真正运行容器的软件，如 containerd、CRI-O                     |

## 三、核心设计理念

**声明式 API + 控制循环（Reconciliation Loop）**：你只需要用 YAML 描述"我想要什么状态"（比如 3 个副本的 nginx），K8s 会持续对比实际状态与期望状态，并自动纠正差异。某个 Pod 挂了，控制器会发现副本数不足，自动拉起新的。

## 四、核心资源对象

### 1. Pod

K8s 中**最小的调度单元**。一个 Pod 包含一个或多个紧密耦合的容器，它们共享网络命名空间（同一个 IP）和存储卷。Pod 是临时性的，随时可能被销毁重建。

### 2. 工作负载控制器

- **Deployment**：管理无状态应用，支持滚动更新、回滚、扩缩容（最常用）
- **ReplicaSet**：保证指定数量的 Pod 副本在运行（通常由 Deployment 管理）
- **StatefulSet**：管理有状态应用（如数据库），提供稳定的网络标识和持久存储，有序部署
- **DaemonSet**：保证每个（或指定的）节点上运行一个 Pod，常用于日志采集、监控代理
- **Job / CronJob**：运行一次性任务 / 定时任务

### 3. 服务发现与网络

- Service

  ：为一组 Pod 提供稳定的访问入口和负载均衡。类型包括：

  - `ClusterIP`：集群内部访问（默认）
  - `NodePort`：通过节点端口对外暴露
  - `LoadBalancer`：借助云厂商负载均衡器对外暴露
  - `ExternalName`：映射到外部 DNS 名称

- **Ingress**：基于域名和路径的 HTTP/HTTPS 七层路由（需要 Ingress Controller，如 Nginx、Traefik）

- **Gateway API**：Ingress 的下一代替代方案，表达能力更强

- **NetworkPolicy**：定义 Pod 之间的网络访问规则（类似防火墙）

### 4. 配置与存储

- **ConfigMap**：存放非敏感配置
- **Secret**：存放敏感信息（密码、令牌、证书）
- **Volume**：Pod 级别的存储
- **PersistentVolume（PV）/ PersistentVolumeClaim（PVC）**：将存储的"提供"与"申请"解耦
- **StorageClass**：动态创建存储卷的模板

### 5. 组织与隔离

- **Namespace**：逻辑隔离，用于多团队、多环境划分
- **Label / Selector**：给资源打标签并按标签筛选，是 K8s 中关联资源的核心机制
- **ResourceQuota / LimitRange**：限制命名空间或容器的资源用量

## 五、核心能力

1. **自动调度**：根据资源需求、节点亲和性/反亲和性、污点与容忍度等策略放置 Pod
2. **自愈**：容器崩溃自动重启，节点故障时将 Pod 迁移到健康节点，健康检查不通过则剔除流量
3. 弹性伸缩
   - HPA：根据 CPU/内存/自定义指标水平扩缩 Pod
   - VPA：自动调整 Pod 的资源请求
   - Cluster Autoscaler：根据负载增减节点
4. **滚动更新与回滚**：逐步替换旧版本 Pod，出问题可一键回滚
5. **服务发现与负载均衡**：通过 DNS（CoreDNS）和 Service 自动实现
6. **配置与密钥管理**：配置与镜像解耦，无需重新构建镜像即可修改
7. **可扩展性**：通过 CRD（自定义资源）和 Operator 模式扩展 K8s，管理复杂应用

## 六、一个简单示例

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: web
spec:
  replicas: 3
  selector:
    matchLabels:
      app: web
  template:
    metadata:
      labels:
        app: web
    spec:
      containers:
      - name: nginx
        image: nginx:1.27
        ports:
        - containerPort: 80
        resources:
          requests:
            cpu: 100m
            memory: 128Mi
          limits:
            cpu: 500m
            memory: 256Mi
---
apiVersion: v1
kind: Service
metadata:
  name: web-svc
spec:
  selector:
    app: web
  ports:
  - port: 80
    targetPort: 80
  type: ClusterIP
```

常用命令：

```bash
kubectl apply -f app.yaml          # 部署
kubectl get pods -o wide           # 查看 Pod
kubectl describe pod <name>        # 查看详情与事件
kubectl logs -f <pod>              # 查看日志
kubectl scale deploy web --replicas=5   # 扩容
kubectl rollout undo deploy web    # 回滚
kubectl exec -it <pod> -- sh       # 进入容器
```

## 七、生态系统

- **包管理**：Helm、Kustomize
- **GitOps / CD**：Argo CD、Flux
- **监控与可观测性**：Prometheus、Grafana、Loki、OpenTelemetry
- **服务网格**：Istio、Linkerd、Cilium
- **网络插件（CNI）**：Calico、Cilium、Flannel
- **安全与策略**：RBAC、OPA/Gatekeeper、Kyverno、Falco
- **本地学习环境**：minikube、kind、k3d、Docker Desktop
- **轻量发行版**：k3s、MicroK8s
- **托管服务**：EKS（AWS）、GKE（Google）、AKS（Azure）、ACK（阿里云）、TKE（腾讯云）、CCE（华为云）

## 八、优缺点

**优点**

- 行业事实标准，生态繁荣，避免厂商锁定
- 高可用、弹性伸缩、自愈能力强
- 声明式管理，适合基础设施即代码和 GitOps
- 可扩展性极强

**缺点**

- 学习曲线陡峭，概念多
- 运维复杂度高（网络、存储、安全、升级都需要专业知识）
- 小型项目可能"杀鸡用牛刀"，资源开销不小
- 有状态应用的管理比无状态应用复杂得多

## 九、适用场景

- 微服务架构的部署与治理
- 需要弹性伸缩的互联网业务
- 多云 / 混合云统一管理
- CI/CD 流水线与多环境交付
- AI/ML 训练与推理平台（GPU 调度）
- 大数据和批处理任务

如果只是部署一两个简单应用，Docker Compose 或云厂商的 PaaS 可能更合适。

## 十、学习路线建议

1. 先掌握 Docker 与容器基础
2. 用 minikube 或 kind 搭建本地集群
3. 学会 Pod、Deployment、Service、ConfigMap、Secret 的使用
4. 学习 Ingress、PV/PVC、StatefulSet、RBAC
5. 学习 Helm、监控（Prometheus）和日志方案
6. 深入网络（CNI）、调度、安全与故障排查
7. 进阶：Operator 开发、GitOps、服务网格；可考虑 CKA / CKAD 认证
